# softradar

СофтРадар – закупки ПО и КП. Стек `python-web`, создан project-kit (`C:\Users\iptvik\projects\project-kit`).

## Контракт с сервером (не ломать)

- Все в одном контейнере `app`, Dockerfile со стадиями `test` (линтер и тесты – CI собирает ее отдельно)
  и `app` (то, что работает на сервере). Новый линтер или тесты – в стадию `test`, не в ci.yml.
- Данные – только в `/data` (переменная `DATA_DIR`), это том; бэкап SQLite – `deploy/backup.sh`, если том есть.
- Веб слушает `PORT` (8080) и отвечает `200` на `/healthz` – по нему CI, деплой и мониторинг понимают,
  что приложение живо. Снаружи HTTPS делает общий edge-caddy, свой TLS не нужен.
- Потолок памяти – `mem_limit` в docker-compose.yml (128m). Сервер общий, на все новые проекты ~2 ГБ.
- Секреты – только в `.env` (на сервере `/opt/softradar/.env`), образец с комментариями – `.env.example`.
  Новая переменная – сразу строка в `.env.example`.
- CI проверяет, что контейнер поднимается без секретов (`.env` пустой). Если приложению без токена
  жить нельзя – пусть пишет понятную ошибку и ждет, а не падает по кругу, или поправь шаг smoke в ci.yml.
- Сервер в России: api.telegram.org недоступен (нужен посредник на Cloudflare Worker, адрес API – в `.env`),
  через Cloudflare большие ответы обрываются после ~64 КБ.

## Выкладка

push в `main` → CI → ветка `deploy` → сервер забирает ее за ~2 минуты. Ждать CI: `gh run list --commit <sha>`,
затем `gh run watch <id> --exit-status`. Деплой: `ssh 185.198.152.76 journalctl -u softradar-deploy -n 30`.
Не собирать образы на сервере и не править файлы в `/opt/softradar` руками – только через git.
