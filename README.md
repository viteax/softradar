# СофтРадар – агент по закупкам ПО на маркетплейсах

Хакатон «ИИкузница» (Softline), трек «Аналитик данных», задача «Робот по работе с маркетплейсами ПО».
Команда «Менталисты».

**Стенд:** https://softradar.iptvik.ru · **API:** `/api/tenders` · **Как работает:** https://softradar.iptvik.ru/about

Агент заменяет ручной мониторинг площадок (2–4 часа в неделю на одну площадку, до 70% сделок пропускается):
каждый час собирает закупки ПО, отсеивает неподходящие по критериям Softline, читает документы закупки,
подбирает товары в каталоге store.softline.ru и готовит менеджеру отчет с приоритетами и черновик КП
по шаблону ПАО «Софтлайн».

## Что делает

1. **Поиск.** Росэлторг (все секции, включая «Мониторинг цен» Росатома, Росэлторг.Бизнес, 223-ФЗ)
   и Фабрикант: 18 поисковых запросов (общие формулировки закупок ПО и ключевые вендоры из задачи),
   только прием заявок, НМЦ ≤ 1 млн ₽. Только открытые страницы, без логинов, как требует заказчик.
2. **Жесткие фильтры (код).** ПО; сумма до 1 млн ₽; подача КП без конкурсной процедуры (аукционы и конкурсы
   отсекаются); исключаются закупки только для МСП; срок приема КП не истек.
3. **Агент (GigaChat, function calling).** Для каждой прошедшей закупки сам решает, какие документы читать
   (запрос КП, ТЗ, проект договора – docx/doc/pdf/xlsx), и через инструменты:
   - `read_document` – читает документ частями;
   - `search_catalog` – ищет товар на store.softline.ru;
   - `get_variants` – получает артикулы семейства с ценами и диапазонами количества;
   - `submit_analysis` – сдает структурированный итог: позиции и количества, НМЦ, срок приема КП,
     **минимальный срок действия КП**, **порядок оплаты**, **формат договора**, **наличие ТЗ**, МСП, риски, резюме.
4. **Расчет (код, без LLM).** Артикул под количество, цены и НДС – только из каталога; если цена каталога выше
   НМЦ – КП по НМЦ; оценка маржи (в каталоге маржи нет – скидка партнера по вендору задается в настройках);
   скоринг 0–100 с объяснением каждого слагаемого.
5. **Результат для менеджера.** Дашборд с вкладками «Подходят / Частично / Ждут анализа / Не подходят /
   Отсеяны фильтром», карточка закупки с ходом работы агента, отчет xlsx, черновик КП docx для каждой
   закупки с найденными позициями. КП – черновик без подписи и печати: менеджер проверяет перед подачей.

Ручной режим: вставить ссылку на закупку Росэлторга/Фабриканта – агент разберет ее сразу.

## Архитектура

```
Площадки ──► sources/roseltorg.py, fabrikant.py (httpx2 + selectolax)
   │
   ▼
filters.py ── критерии Softline (детерминированно)
   │
   ▼
карточка + документы (docs.py: docx/doc/pdf/xlsx/rtf → текст, кэш в SQLite)
   │
   ▼
agent.py ── GigaChat function calling, до 12 шагов
   │          read_document → search_catalog → get_variants → submit_analysis
   ▼
catalog.py ── store.softline.ru: поиск + JSON артикулов со страницы товара (кэш 12 ч)
pricing.py ── артикул под количество, итоги, НДС, НМЦ-кап, маржа, скоринг
kp.py ─────── черновик КП (docx по шаблону Softline), отчет (xlsx)
web.py ────── дашборд, карточки, API; фоновый прогон каждые RUN_INTERVAL_MIN минут
```

Где решает модель: выбор документов, извлечение условий из свободного текста, сопоставление позиций
с товарами каталога, риски. Где код: все цифры (цены, количества, суммы, маржа, балл) и фильтры.
Проверка ответа модели: ссылки на товары сверяются с каталогом, цена берется из каталога по артикулу,
позиции без артикула помечаются «нет в каталоге», вердикт «подходит на 100%» ставит код, а не модель.

## Стек

Python 3.14, Starlette + Jinja2, httpx2, selectolax (lexbor), python-docx, openpyxl, pypdf, SQLite.
LLM – GigaChat Ultra (`GigaChat-3-Ultra`, API Сбера, российский контур); вторым провайдером поддержан OpenAI-совместимый API cloud.ru Foundation Models (`LLM_PROVIDER=openai`, например `GigaChat/GigaChat-4-708B-A41`). Выбор модели – по замеру `scripts/compare_models.py`, экономика – `docs/softradar_cost.xlsx`. Docker, GitHub Actions → ghcr.io →
VPS в РФ (площадки доступны из РФ), HTTPS через Caddy.

## Запуск

```bash
cp .env.example .env            # GIGACHAT_AUTH_KEY – ключ авторизации GigaChat
docker compose up -d --build    # http://localhost:8080
# или локально:
uv sync && uv run python -m app
```

Тесты: `uv run pytest` (парсеры на сохраненных страницах площадок, фильтры, экономика, КП, веб).

Настройки (`.env.example`): площадки, поисковые запросы, интервал, лимит суммы, порог маржи,
скидки по вендорам, провайдер и модель LLM, цены токенов.

## API

- `GET /api/tenders?verdict=fit|partial|reject` – закупки с анализом и строками КП
- `GET /api/tenders/{key}` – одна закупка, включая ход работы агента
- `GET /t/{key}/kp.docx` – черновик КП, `GET /report.xlsx` – отчет
- `POST /run` – запустить прогон, `GET /api/status` – прогресс

## Ограничения прототипа

- Площадки: Росэлторг и Фабрикант. Остальные из списка заказчика (ГПБ, Сбер, B2B-Center, Мосрег и др.)
  подключаются модулем в `app/sources/` с той же парой функций `search`/`detail`.
- Отчет менеджеру – на дашборде и в xlsx; рассылка на почту не подключена (нужен SMTP заказчика).
- Маржа – оценка по допущению о скидке партнера от розничной цены каталога (настраивается).
- Цены каталога – розничные с сайта; специальные цены Softline для госзаказчиков не учитываются.
